1. Resumen ejecutivo

La revista ya no muestra solo tarjetas: ahora el documento curado se refleja en el visor visual. Al publicar, el contenido ocupa la página 1, luego la 2, la 3 y así sucesivamente. El artículo actual detectó 11 páginas desde el ODT y dejó 10 marcadores [[PAGINA]] en el contenido curado.

2. Lo implementado

2.1 Proveedor de IA y MCP

  • OPENAI_BASE_URL apunta al endpoint compatible de Gemini: https://generativelanguage.googleapis.com/v1beta/openai/.
  • CURACION_MODEL y DIAGNOSTICO_MODEL usan gemini-3.5-flash-lite.
  • El MCP de curación quedó escuchando en http://localhost:3001/mcp y responde a curar_contenido con páginas y marcadores.
  • Una prueba real con el ODT devolvió paginas_originales: 11, marcadores: 10 y contenido paginado.

2.2 Revista visual y Plano General

  • /revista consulta simultáneamente artículos públicos y piezas aprobadas del estudio editorial.
  • El Plano General muestra las 16 páginas base y una sección «Piezas del estudio editorial».
  • Cada pieza permite Vista previa, Publicar, Ver en visor, Quitar y Eliminar.
  • Después de publicar, el visor vuelve a la página 1 con un aviso confirmando la operación.
  • Las imágenes firmadas de Supabase Storage se renuevan automáticamente antes de mostrarse.

2.3 Contenido paginado

  • El extractor detecta saltos de página reales en ODT (text:soft-page-break, fo:break-before="page"), DOCX (w:br, w:pageBreakBefore) y marcadores manuales en texto/Markdown.
  • El prompt de curación pide conserve los marcadores [[PAGINA]] y distribuya el texto sin perder información.
  • El endpoint POST /api/curation/articulos/[id]/reprocesar permite adaptar un artículo ya subido sin volver a cargar el archivo.
  • El botón «Adaptar a páginas» está disponible en el historial del estudio editorial.

2.4 Publicar y despublicar

AcciónQué haceReversible
AprobarFija la versión activa y deja estado = 'aprobado'. La pieza aparece en el Plano General, pero no en la API pública.Sí
PublicarFija la versión activa, copia título/resumen/contenido al artículo y escribe estado = 'publicado' con published_at.Sí, quitándolo
Quitar de revistaPasa el artículo a borrador y limpia published_at. Desaparece del visor y del Plano General, pero conserva versiones.Sí
Eliminar definitivamenteBorra el artículo, sus versiones por cascada y los archivos en Storage.No

3. Cómo levantar la aplicación

3.1 Preparación única

  1. Tener Node.js 18 o superior y npm instalados.
  2. Ejecutar en Supabase → SQL Editor el archivo supabase/setup-completo.sql.
  3. En Supabase → Authentication → Providers, mantener Email activo. Configurar: 
    Site URL: http://localhost:3000
Redirect URLs: http://localhost:3000/**
  4. Copiar la plantilla de variables y completarla: 
    cp .env.example .env.local
    Variables mínimas: 
    NEXT_PUBLIC_SUPABASE_URL=https://TU-PROYECTO.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
MCP_CURACION_URL=http://localhost:3001/mcp
MCP_DIAGNOSTICO_URL=http://localhost:3002/mcp
MCP_ALLOWED_HOSTS=TU-PROYECTO.supabase.co
OPENAI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
OPENAI_API_KEY=...
CURACION_MODEL=gemini-3.5-flash-lite
DIAGNOSTICO_MODEL=gemini-3.5-flash-lite
  5. Instalar dependencias de la app y de los MCP: 
    npm install
npm install --prefix mcp/curation
npm install --prefix mcp/diagnostic

5. Tutorial: cómo publicar en la revista

5.1 Requisitos previos

  1. Tener el proyecto Supabase conectado y las migraciones aplicadas.
  2. Iniciar la app con npm run dev.
  3. Iniciar el MCP de curación: 
    cd mcp/curation
npm run dev
    Debe aparecer mcp-curacion escuchando en http://localhost:3001/mcp.
  4. Ingresar a http://localhost:3000/acceso con un usuario con rol editor o admin.
  5. Si tu usuario aún no es editor, ejecutar en Supabase → SQL Editor: 
    update public.usuarios
set rol = 'editor'
where nombre = 'ekn47';
Sin el MCP levantado, la subida y la generación de versiones fallan. La publicación desde el Plano General depende de que ya exista una versión aprobada.

5.2 Flujo desde el estudio editorial

Entrar a /editor. Sube un documento .odt, .docx, .md o .txt de hasta 20 MB. Puedes añadir imágenes.
Esperar las versiones curadas. El MCP extrae el documento, detecta los saltos de página y genera variantes con Gemini.
Si el artículo venía de una curación anterior, pulsar «Adaptar a páginas». Esto reprocesa el archivo guardado y asegura los marcadores [[PAGINA]] sin volver a subirlo.
Elegir una versión. «Aprobar» la deja lista sin publicar; «Publicar en revista» la publica de una vez y copia su contenido al artículo.
Verificar en /revista. Abre el menú del visor y entra a «Plano General»: la pieza aparece en «Piezas del estudio editorial» con badge «Publicado».
Publicar desde el visor si aún estaba aprobada. En la tarjeta o en la vista previa, pulsar «Publicar». El visor vuelve automáticamente a la página 1.
Recargar con Ctrl+F5. La portada y las siguientes páginas mostrarán el contenido real del documento.

5.3 Qué ocurre al publicar

  • estado = 'publicado' y published_at = now() en public.articulos.
  • version_activa_id apunta a la versión elegida.
  • El contenido con marcadores [[PAGINA]] se divide y ocupa las páginas 1, 2, 3… del visor.
  • La tarjeta pública aparece en la sección inferior de /revista y en GET /api/revista/articulos.

6. Tutorial: cómo quitar o borrar la publicación

6.1 Quitar de la revista (recomendado, reversible)

Úsalo cuando quieras que el artículo deje de verse, pero conserves el historial de curación para volver a publicarlo después.

  1. Entrar a /revista y abrir el Plano General, o entrar a /editor con el artículo cargado.
  2. Buscar la pieza y pulsar «Quitar» en la tarjeta, «Quitar de revista» en la vista previa o en el historial.
  3. Confirmar el aviso del navegador.
  4. Recargar con Ctrl+F5.

Internamente se ejecuta:

PATCH /api/curation/articulos/[id]/estado
{ "estado": "borrador" }

Equivalente SQL si necesitas hacerlo desde Supabase:

update public.articulos
set estado = 'borrador', published_at = null
where id = 'ddab7db1-e664-47c5-9af7-90915f05585f';
Resultado: desaparece del visor, del Plano General y de la API pública. Las versiones siguen en curacion_versiones.

6.2 Eliminar definitivamente

Borra el artículo, todas sus versiones y los archivos asociados en Storage. No se puede deshacer.

  1. Entrar a /revista → Plano General, o a /editor.
  2. Pulsar «Eliminar» o «Eliminar definitivamente».
  3. Confirmar el aviso: «¿Eliminar definitivamente el artículo, sus versiones y sus archivos?».
  4. Recargar con Ctrl+F5.

Internamente se ejecuta:

DELETE /api/curation/articulos/[id]

Equivalente SQL:

delete from public.articulos
where id = 'ddab7db1-e664-47c5-9af7-90915f05585f';
Importante: la eliminación en cascada borra las versiones, pero los objetos en Storage se eliminan de forma independiente desde el endpoint. Si borras solo con SQL, los archivos del bucket permanecen.

8. Estado y recomendaciones

  • Rotar la key de Gemini que quedó expuesta en el chat y actualizar .env.local y el MCP si se cambia.
  • Eliminar la service role key antigua en Supabase → Settings → API Keys si todavía aparece.
  • No ejecutar npm run build ni borrar .next mientras npm run dev esté activo. Si ocurre, reinicia el dev server.
  • Deploy pendiente: en Vercel habría que adaptar los MCP locales antes de publicar el estudio editorial.
  • Paginación actual: el documento cargado produce 11 páginas. Las páginas 12 a 16 del visor permanecen con contenido base porque no hay saltos para ellas.
Con este informe, cualquier editor puede publicar una pieza, verla en la Revista Digital y retirarla o eliminarla sin depender de SQL, excepto en los casos de administración directa.
