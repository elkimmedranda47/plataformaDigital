2. Qué funciona hoy

  • Registro e ingreso en /acceso con email y contraseña, sin confirmación de correo en este entorno de pruebas.
  • Creación automática de perfil en public.usuarios mediante el trigger handle_new_user().
  • Primera publicación en /publicar: portada en Storage, diagnóstico y proyecto con consentimiento explícito.
  • Top 10 en /top10: ranking semanal, likes, estrellas y comentarios. Lectura pública, escritura con sesión.
  • Revista pública en /revista: artículos con estado publicado, ordenados por fecha.
  • Estudio editorial en /editor: subida de documento, generación de versiones y botón «Publicar en revista», siempre que el MCP de curación esté activo.

La publicación de emprendimientos y las interacciones del Top 10 no dependen de los MCP. Solo la curación asistida y el diagnóstico con LLM los necesitan.

3. Cómo publicar en la revista

3.1 Flujo completo desde el estudio editorial

  1. Promover tu usuario a editor en Supabase → SQL Editor: 
    update public.usuarios
set rol = 'editor'
where nombre = 'ekn47';

select nombre, rol from public.usuarios;
  2. Entrar a /editor y subir un archivo .docx, .odt, .md o .txt (máximo 20 MB). Opcionalmente, imágenes.
  3. Esperar las versiones generadas por el MCP de curación en localhost:3001/mcp.
  4. En «Historial de curación», pulsar «Aprobar» o directamente «Publicar en revista» en la versión elegida.
  5. El endpoint PATCH /api/curation/versions/:id/select copia título, resumen y contenido de la versión al artículo, fija estado = 'publicado' y escribe published_at.
  6. Recargar /revista: el artículo aparece como tarjeta pública.
Si el MCP no está levantado, la subida fallará. Para probar la revista sin MCP puedes usar el atajo SQL de abajo.

3.2 Atajo directo sin MCP

insert into public.articulos
  (editor_id, titulo, slug, resumen, contenido_md, estado, published_at)
select
  id,
  'Mi primer artículo',
  'mi-primer-articulo-' || floor(extract(epoch from now()))::text,
  'Resumen corto que aparece en la tarjeta.',
  'Contenido en Markdown del artículo.',
  'publicado',
  now()
from public.usuarios
where nombre = 'ekn47';

Después ejecuta select titulo, estado, published_at from public.articulos; y recarga /revista.

Resumen operativo: para entregar la revista completa con el flujo editorial, sube 20 documentos (uno por artículo) y 20 portadas como mínimo; si subes el máximo permitido en el estudio editorial serían 100 imágenes (5 por documento). Para la revista visual de 16 páginas no hay que subir nada adicional: ya viene cargada, y cada publicación desde /publicar solo añade 1 portada que ocupa la página 5.

5. Despliegue gratuito con Vercel (recomendado)

  1. Sube el repositorio a GitHub, GitLab o Bitbucket. Verifica que .env.local no se suba: ya está en .gitignore.
  2. En Vercel, inicia sesión y pulsa Add New → Project.
  3. Importa el repositorio. Deja Root Directory en la raíz y Framework Preset en Next.js. Vercel detecta npm install y npm run build.
  4. Antes de desplegar, abre Environment Variables y carga las mismas variables de .env.local (sección 6). Marca los ambientes Production, Preview y Development según convenga.
  5. Pulsa Deploy y espera el build. Copia la URL resultante, por ejemplo https://talento-tech-valle.vercel.app.
  6. En Supabase → Authentication → URL Configuration, cambia: 
    Site URL = https://talento-tech-valle.vercel.app
Redirect URLs = https://talento-tech-valle.vercel.app/**
    Conserva http://localhost:3000/** si todavía vas a probar en local.
  7. Si cambiaste variables después del primer deploy, haz Redeploy.
  8. Opcional: en Vercel → Settings → Domains puedes añadir un dominio propio y repetir el paso 6 con ese dominio.
El plan Hobby de Vercel es gratuito para proyectos personales o de demostración. Supabase Free y Vercel Hobby tienen límites de uso; revisa las cuotas antes de compartir el enlace públicamente.

7. Ajustes en Supabase para producción

  1. URLs de Auth: Site URL y Redirect URLs apuntando al dominio de Vercel, como se indicó arriba.
  2. Confirm email: en producción conviene reactivar Confirm email. El plan gratuito de Supabase envía un número muy limitado de correos por hora; para uso real configura SMTP propio en Authentication → Emails.
  3. Registro abierto: mantén Allow new users to sign up activo si cualquier visitante debe crear cuenta. Si será una beta cerrada, desactívalo y crea usuarios desde Authentication → Users.
  4. RLS: revisa que las políticas sigan siendo explícitas. La service role key bypassea RLS, por eso solo debe vivir en el servidor.
  5. Roles: asigna editor o admin solo a cuentas de confianza: 
    update public.usuarios u
set rol = 'editor'
from auth.users a
where a.id = u.id and a.email = 'editor@ejemplo.com';

9. Verificación post-deploy

  1. Abrir https://TU-DOMINIO.vercel.app/api/proyectos. Debe responder {"proyectos":[],"configurado":true,"usuarioId":null} o con proyectos, pero nunca "configurado":false.
  2. Abrir /acceso, crear cuenta e iniciar sesión. Revisar en Supabase → Table Editor que apareció el perfil.
  3. Probar /publicar y después /top10: like, estrellas y comentario.
  4. Publicar un artículo por SQL o desde /editor yConfirmar que aparece en /revista.
  5. Revisar la pestaña Logs de Vercel y los logs de Supabase si alguna escritura falla.

En local, la comprobación equivalente es:

curl -s http://localhost:3000/api/proyectos
curl -s http://localhost:3000/api/revista/articulos
npx tsc --noEmit
npm run lint

Ambos comandos de calidad ya pasan sin errores en el estado actual del repositorio.

10. Pendientes y recomendaciones

  1. Eliminar la service role key antigua en Supabase → Settings → API Keys.
  2. Desplegar los MCP en un hosting gratuito (Railway/Render/Fly.io) y reemplazar MCP_CURACION_URL y MCP_DIAGNOSTICO_URL con sus URLs públicas si se quiere usar /editor en producción.
  3. Configurar OPENAI_API_KEY real en el hosting de los MCP.
  4. Reactivar Confirm email y configurar SMTP antes de abrir registros al público.
  5. Añadir rate limiting en likes, calificaciones y comentarios.
  6. Sanitizar Markdown con rehype-sanitize si en el futuro se renderiza como HTML en la revista.
  7. Conectar el diagnóstico al MCP para sustituir el scoring local por el reporte de IA.
